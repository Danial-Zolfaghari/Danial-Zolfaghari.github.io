Server Analytics — External Flask Command Center

Outside the game process · Read-only MySQL

Project developed by Danial Zolfaghari (دانیال ذوالفقاری). Operations · FiveM.

Project overview

Standalone Flask Command Center running outside the game process — read-only MySQL, separate SQLite security layer, KPI dashboards, Activity Score analytics, and 15+ operational modules.

Whole-server intelligence without touching the live game process — the same engineering instinct behind VIDA and Razhman analytics, applied to a FiveM production platform.

Gave operators whole-server KPIs and Activity Score analytics without risking the live game process — read-only data access with a separate security layer.

In-game admin tools could not safely expose whole-server analytics — coupling heavy queries to the live game process risked tick stability and mixed operator security with player sessions.

Engineered a standalone Flask Command Center: read-only MySQL from outside FXServer, SQLite-backed operator security, KPI dashboards, and Activity Score modules — 15+ operational views without touching the game loop.

System architecture

  • Panel: Flask + JavaScript — KPI dashboards, Activity Score, 15+ modules
  • Security: SQLite operator layer — auth and access isolated from game DB writes
  • Data: Read-only MySQL — whole-server queries without touching live resources
  • Runtime: Separate Linux process — independent from FXServer tick loop
