ANDE — Adaptive Network Defence Engine

Read-only · Layer-1 → Admin → ML

Project developed by Danial Zolfaghari (دانیال ذوالفقاری). Security · Razhman.

Project overview

Read-only network traffic analysis console for L3/L4 DoS/DDoS triage — Layer-1 heuristics, Discovery proposals, Admin ground truth, and offline ML scoring over Elasticsearch.

ANDE (Adaptive Network Defence Engine) is a read-only operations console: Elasticsearch search, live rule-window analysis, SSH mitigator config inspection, and local ground-truth labeling. Layer-1 heuristics catch obvious spikes; Discovery proposes; Admin decides; offline export trains Random Forest and XGBoost — prediction never becomes ground truth and live path never mitigates traffic.

SOC-grade read-only analysis console that separates detection triage from mitigation — Layer-1 floors, human Admin ground truth, and optional ML hints without ever writing to Elasticsearch or changing drop rules.

During active L3/L4 incidents, analysts needed faster DoS/DDoS triage than manual Kibana queries — but any tool that auto-mitigated or auto-labeled traffic would corrupt ground truth and create operational risk.

Built ANDE as a read-only analysis console: LiveEngine polls Elasticsearch every 2s, Layer-1 heuristics score obvious spikes, Discovery proposes candidates on 2-minute windows, and Admin Review is the sole ground-truth source — offline Random Forest/XGBoost trains later and live ML scores are hints only.

Engineering highlights

  • Engineered LiveEngine with 30s detection, 2m Discovery, and 15m traffic chart windows — never collapsed into one query semantics
  • Built Layer-1 fixed heuristics for DoS/DDoS classification (source cardinality) with PPS floor bands and Under Attack /32 rules
  • Designed triage cascade: Discovery proposes → Admin Review writes ground truth → offline ML trains only after readiness gates
  • Shipped React SPA with WebSocket snapshot push, Explain drawer, Rule History JSONL, and Pattern Intelligence
  • Enforced safety invariants: read-only ES, SSH cat-only mitigator inspect, prediction ≠ ground truth, live ≠ train

System architecture

  • Frontend: React + TypeScript + Vite — web/dist, ANDE charcoal + lime theme, WebSocket /api/live/ws
  • API: FastAPI network_ai.live.api — cookie session, CSRF, IdentityStore, LiveHub snapshot push
  • Collectors: LiveEngine ~2s, DiscoveryEngine ~2m, RuleServerMonitor SSH keepalive 60s, RuleHistoryStore JSONL
  • Analysis: Windows → Layer-1 heuristics → Labeling → Talkers explain → Snapshot compact rules
  • External: Elasticsearch read-only search + SSH mitigator rule-2-drop.cfg cat-only
  • ML (Offline): Admin GT JSONL → dataset export → Random Forest + XGBoost — never on live path
